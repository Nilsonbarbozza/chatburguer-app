📜 ORDEM DE SERVIÇO: OS-007 (Operação Visão de Raio-X)
De: Arquiteto-Chefe / Comando Geral
Para: Esquadrão de Código
Alvo: agentic_api/routes.py, core/database.py e tools/neural_keymaster.py
Objetivo: Persistir a telemetria do Radar Comercial no PostgreSQL e criar painéis analíticos no terminal do CEO.

🗄️ Fase 1: O Esquema Relacional (Postgres)
O Esquadrão deve criar uma nova tabela no banco de dados chamada commercial_radar.

Colunas Obrigatórias:

id (UUID ou Serial)

api_key_hash (Para cruzar com o cliente, evitem salvar a chave em texto plano puro se possível, ou usem o client_name diretamente)

target_domain (ex: mining-data.com)

endpoint_used (ex: /fetch ou /search_and_fetch)

status_code (ex: 200 para sucesso, 403 para WAF block - vital para sabermos se o cliente está apanhando de firewalls)

timestamp (Data e hora exata)

⚡ Fase 2: Inserção Assíncrona (A Regra de Ouro da Latência)
Diretiva Crítica de Arquitetura: O ato de salvar no banco de dados NÃO PODE atrasar a resposta da API para o cliente.

O Esquadrão deve usar o recurso BackgroundTasks do FastAPI (ou disparar via ARQ). O cliente recebe o Markdown instantaneamente e, em segundo plano (background), a API faz o INSERT no PostgreSQL silenciosamente.

🛠️ Fase 3: O Upgrade do Bastão (neural_keymaster.py)
Adicionar dois novos poderes ao arsenal do CLI:

analytics (Visão Global):

Ação: Faz um SELECT agrupado e mostra um Top 5 dos domínios mais raspados por toda a base, além da taxa de sucesso (quantos 200 OK vs quantos 403 WAF Block).

list-targets (Visão Sniper):

Entrada: --key sk-xxx ou --client "Nokia"

Ação: Retorna os últimos 10 domínios específicos que aquele cliente tentou raspar.

Com essa OS concluída, o seu ecossistema estará 100% blindado: o Redis controlando o dinheiro (cotas) e o Postgres controlando a inteligência (auditoria).
