📜 ORDEM DE SERVIÇO: OS-006 (Operação Catraca Inteligente)
De: Arquiteto-Chefe / Comando Geral
Para: Esquadrão de Código
Alvo: agentic_api/auth.py (e injeção de dependência nas rotas)
Objetivo: Integrar a validação de chaves e o débito de cotas do Redis diretamente no fluxo de requisições do FastAPI, implementando o bloqueio comercial (HTTP 402).

🎯 O Briefing Estratégico
Nossa API deixará de aceitar acessos anônimos ou chaves fixas de teste (dev-key-001). Cada requisição HTTP batendo em /fetch ou /search_and_fetch deve passar pelo crivo do Redis. Se o cliente tiver saldo, a requisição passa e debita 1 crédito. Se não tiver, o sistema ejeta a conexão com a mensagem comercial do CEO.

⚙️ Fase 1: A Lógica de Interceptação (auth.py)
O Esquadrão deve reescrever a função de dependência de autenticação (geralmente get_api_key ou verify_token) para executar o seguinte fluxo assíncrono:

Captura: Extrair a chave do header X-API-Key (ou Authorization: Bearer).

Busca no Redis: Fazer um HGETALL na chave auth:key:{api_key}.

Validação de Existência/Status:

Se a chave não existir no Redis OU o status for revoked:

Ação: Retornar HTTP 401 Unauthorized (Credencial inválida ou revogada).

Validação Comercial (A Catraca):

Comparar os inteiros: quota_used vs quota_limit.

Se quota_used >= quota_limit:

Ação: Retornar HTTP 402 Payment Required.

Payload do Erro: {"detail": "Limites do Trial NeuralSafety atingidos. Entre em contato diretamente com Nilson Barbozza para liberação e upgrade para a licença Enterprise."}

Débito Atômico:

Se a chave for válida e tiver saldo, o sistema DEVE incrementar o uso.

Ação Tática: Utilizar o comando Redis HINCRBY auth:key:{api_key} quota_used 1. (Nota para a engenharia: Use o incremento atômico do Redis, não puxe o valor para o Python para somar e depois salvar, isso evita Race Conditions se o cliente disparar 100 requisições simultâneas).

🛡️ Fase 2: Injeção de Dependência (routes.py)
Garantir que os endpoints da API (ex: POST /v1/agent/fetch) estejam exigindo a dependência de segurança que acabamos de criar. Nenhuma rota pode ficar desprotegida.

📊 Fase 3: Cabeçalhos de Resposta (Opcional, mas Recomendado)
Para uma experiência Enterprise, o middleware de autenticação deve retornar ao cliente (via HTTP Headers de resposta) quantos créditos ele ainda tem.
Exemplo:

X-RateLimit-Remaining: 499
Isso permite que a IA do cliente saiba quando o saldo está acabando sem precisar tomar um erro 402 "de surpresa".

🎯 Definition of Done (Critérios de Aceite)
A missão será considerada cumprida quando:

Uma requisição com uma chave forjada no neural_keymaster passar com sucesso e o contador quota_used subir para 1.

Quando a chave bater no limite (ex: 500/500), a 501ª requisição for bloqueada imediatamente com o erro 402 Payment Required e a mensagem do CEO.

Uma chave revogada tomar erro 401.
