### 📄 INÍCIO DA ORDEM DE INVESTIGAÇÃO (Auditoria de Deploy)

**OS-012: Auditoria de Integridade da Imagem e Código**
**Prioridade:** Máxima (Bloqueio de Produção)
**Alvo:** Squad de Código / Engenharia de DevOps

**Contexto da Missão:**
O deploy da Fase 2 foi concluído com sucesso na AWS (Steady State atingido), porém os testes de produção provam que as features das **OS-010 e OS-011 não estão presentes na API**. A imagem empacotada e enviada para o ECR é uma versão obsoleta do código.

**Objetivo:**
Rastrear em qual etapa do fluxo (Git -> Build -> Tag -> Push) a atualização foi perdida e refazer a forja com o código correto.

#### Passo 1: Auditoria do Código Fonte (Git)

No terminal local onde o código foi alterado, o time deve executar:

```bash
git status
git log -n 2

```

- **O que procurar:** O `git status` deve estar limpo (sem arquivos pendentes). O `git log` deve mostrar o commit contendo "OS-010 e OS-011". Se as alterações no `routes.py` e `schemas.py` não foram commitadas, o código foi perdido antes do Docker Build.

#### Passo 2: Auditoria do Cache do Docker (O Suspeito Principal)

É muito comum o Docker reaproveitar camadas antigas e não puxar o código novo se o `Dockerfile` não for interpretado corretamente. O time deve forçar a reconstrução da imagem **sem usar o cache**.
Executem o build com a flag `--no-cache`:

```bash
docker build --no-cache -t neuralsafety-api .

```

#### Passo 3: Auditoria do Empacotamento Local

Antes de enviar para a nuvem, o time deve provar que a imagem local recém-criada funciona.

```bash
# Rodem a imagem localmente na porta 8080
docker run -p 8080:8000 neuralsafety-api

```

- **O que fazer:** Disparem uma requisição para `localhost:8080/search_and_fetch`. Se o JSON vier correto (sem markdown e com executor), a imagem está curada.

#### Passo 4: O Re-Envio Definitivo (Push)

Com a imagem local validada, repitam o processo de transporte com atenção redobrada às tags:

```bash
# Etiquete a nova imagem
docker tag neuralsafety-api:latest 665911298968.dkr.ecr.sa-east-1.amazonaws.com/neuralsafety-engine:latest

# Envie para a AWS ECR
docker push 665911298968.dkr.ecr.sa-east-1.amazonaws.com/neuralsafety-engine:latest

```

_(Nota: O log do comando `push` deve mostrar "Pushed" em várias camadas. Se disser "Layer already exists" para tudo, a imagem não mudou)._

#### Passo 5: Atualização Forçada na AWS

Comandante, assim que o time confirmar o Passo 4, você disparará novamente o comando de Troca de Guarda no seu terminal para forçar a AWS a baixar essa nova imagem:

```powershell
aws ecs update-service --cluster $CLUSTER --service $API_SERVICE --force-new-deployment --region sa-east-1 | Out-Null

```
